## Rule Governance Framework

### Core Principles
- Follow established rules as professional guidelines
- Apply judgment and experience when rules are unclear
- Maintain consistency while allowing for context-appropriate flexibility
- Use rules as a foundation, not as absolute constraints

### Rule Application Guidelines
1. **Primary Rules**: Rules in @.agent/rules provide the foundation
2. **Contextual Judgment**: Apply rules appropriately to the situation
3. **Conflict Resolution**: When rules conflict, use professional judgment
4. **Rule Evolution**: Rules may be updated to reflect best practices

### Professional Conduct
- **Rule Compliance**: Follow rules as professional standards
- **Flexibility**: Adapt application based on context and requirements
- **Transparency**: Document when and why rules are applied differently
- **Continuous Improvement**: Suggest rule improvements when appropriate

### Decision Making Framework
1. **Check Existing Rules**: Review applicable rules first
2. **Assess Context**: Consider specific situation requirements
3. **Apply Professional Judgment**: Use experience and best practices
4. **Document Rationale**: Explain decisions when deviating from norms
5. **Seek Clarification**: When uncertainty exists about proper approach

### Modern Development Practices (2026)
- **AI-Assisted Development**: Rules support, not replace, AI judgment
- **Agile Adaptation**: Rules evolve with technology and practices
- **Outcome Focus**: Rules serve quality outcomes, not bureaucracy
- **Collaborative Improvement**: Team input shapes rule evolution
- **Automated Compliance**: Rules integrated with development tools

### Rule Hierarchy
1. **Security & Compliance**: Absolute priorities
2. **Quality Standards**: High importance
3. **Process Guidelines**: Flexible application
4. **Stylistic Preferences**: Lowest priority

### Rule Maintenance
- Regular review to ensure relevance
- Update to reflect current best practices
- Remove outdated or counterproductive rules
- Add rules for emerging technologies and patterns

### Common Pitfalls
- Applying rules too rigidly without context
- Ignoring rules when they're inconvenient
- Failing to document rationale for deviations
- Not updating rules as practices evolve
- Overcomplicating rule application

### When to Use
- All development activities
- Rule interpretation questions
- Conflict resolution between rules
- Rule evolution and updates
- Governance decisions

### When Not to Use
- When explicit rule overrides are requested
- For experimental or research projects
- When testing new approaches
- In emergency situations requiring immediate action

### Governance Process
1. **Rule Proposal**: Submit through governance channel
2. **Review**: Team evaluation and feedback
3. **Approval**: Consensus-based decision
4. **Implementation**: Documentation and communication
5. **Monitoring**: Track effectiveness and usage
6. **Iteration**: Regular review and improvement

### Change Management
- **Minor Updates**: Editorial changes, clarifications
- **Major Updates**: New rules, significant changes
- **Deprecation**: Mark outdated rules clearly
- **Sunsetting**: Remove obsolete rules
